# Agent Note: 会话附属卡片与子智能体目录分类

Status: implemented

[English](2026-11-10-session-attachment-cards.md) | 中文

## Problem

为用户对话执行后台工作的业务插件需要宿主提供两项它自己无法提供的能力。第一，它必须在实际展示的 Session 中的真实位置显示卡片——正在处理的那一轮的轮首、触发它的事件、结束该轮的真实 `turn/end`，或它提交的那次精确工具调用——同时时间线仍在滚动、折叠、分页，并在 fork 与其来源之间切换。第二，它必须把已在别处提供入口的子智能体从原生子智能体菜单中移除，同时不失去原生目录的地址、谱系与全局活动计数。

既有接点都表达不了这两件事。`conversation.chat.turnTail` 只在已关闭轮次的页脚内渲染，并且拿到的是收尾回复的序号，而不是该轮自身的结束；运行中的轮首没有任何位置；插件自己的卡片也无法指向它所属的某条已加载行。原生菜单直接从投影读取行、总数、运行数与空态，没有留给业务判定的位置。

## Decision

**`ctx.uiConversation.attachments` 负责注册，`conversation.chat.attachment` 负责渲染。** 注册项携带稳定卡片 ID、实际展示的 Session、优先侧别，以及一个耐久锚点：`turn-start`；带 Session seq 的 `event`；`turn-end`；或带 callId 的 `tool-call`。卡片移动后 ID 保持不变；注册表按 Session 发布身份稳定的来源，并在注册被撤回时移除卡片。按键的 Slot 携带 owner 数据渲染卡片，因此插件拥有数据与寿命，宿主拥有位置。

**Chat 目标把锚点解析到已加载时间线，从不保存行下标。** `turn-start` 与 `turn-end` 读取公开的 `TimelineSnapshot` 轮次边界，因此分页、折叠与移动是同一判定，已结束但没有最终回复的轮次同样有真实轮尾。`event` 先匹配唯一一条把该耐久 seq 声明为新 `sourceSeq` 的已加载根行。`step/start` 没有自己的行，因此同一锚点随后匹配 `StepLocation.start.seq` 即该 seq 的已加载 Step，并挂在该步第一条可见行上；折叠时由所属原生过程组与整轮入口保持可达。两者都不成立的 seq 保留该轮轮首。行的 `anchorSeq` 只是可排序的渲染位置，可能是瞬态小数，因此绝不与耐久 seq 比较。`tool-call` 按已加载 Tool Node 自身的 callId 匹配，调用未加载、属于另一轮或重复时回退到该轮入口；相邻关系从不代替调用身份。未加载的轮次不挂载任何内容，直到对应页到达；fork 有自己的 Session 身份，不会收到为其来源注册的卡片。

**视口测量内容列旁的留白，并在侧边留白与轮内位置之间选择。** 侧边布局是一次测量比较，而不是媒体断点：内容宽度是会话宽度与用户偏好的 `clamp()`，CSS 无法比较这两个动态长度。该判定以列属性传达给 CSS，并以每张卡片自己的 host 属性传达给该卡，行则只在其中每张卡片都使用留白时报告 `side`。侧边卡片脱离文档流，因此出现、移动或消失都不会推动正文或写入滚动位置；它与原生时间线共用滚动容器，并站在解析位置旁的留白中。每一侧最多只用留白承载一张 `auto` 卡片：该侧解析出的 `auto` 卡片多于一张时，它们都不使用留白并全部留在文档流中，因为第二张侧边卡会站在邻近但未测量的锚点上并可能盖住第一张。以 `presentation: 'inline'` 注册的卡片始终留在所属轮内，也不占用该容量，因此业务可以让历史入口留在原位，同时活动卡保住侧边；不设置即等同 `auto`，且每张卡片保留自己的 host，历史卡与活动卡解析到同一侧同一位置时活动卡仍进入留白。两种布局共用一次挂载，改变宽度只改变位置，卡片、其 DOM 节点与内部焦点都保持。侧边卡片会把该留白标记为已占用，所在行里的宽 Markdown 表格因此留在内容列内，不再越出到卡片下方；承载侧边卡片的过程组取消高度上限，因为带上限的正文是滚动容器，会裁掉留白。

**行内宿主卡片指名唯一渲染条目。** 挂在 Tool 调用行或步入口上的卡片指向确切的渲染条目（含 Assistant 分段），因此被呈现两次的节点（推理段与回复行）只挂一份；行都在过程组内的步则以该组的可见入口为目标，由组自身的开合保持可达。视口向解析器提供分组归属，宿主不再按行顺序猜测组。

**`ctx.subagentMenu` 负责菜单分类。** 分类器接收实际父级 `SessionId` 与完整原生条目，返回它已在别处提供入口的条目，并发布在其证据变化时重新发布菜单的可观察 revision。这同一个结论过滤后代计数菜单的行、总数、运行数与空态；面包屑切换器、地址、打开子会话以及工作区级运行指示继续使用完整原生目录。分类器抛错、返回 `undefined`，或返回无法读取的结果时视为不可用且不贡献条目，原生行保留；撤回注册即恢复它们，且证据订阅释放失败不会留下失效分类器。

## Alternatives considered

**复用 `conversation.chat.turnTail` 并新增轮首列表 Slot。** 否决：`turnTail` 属于已关闭轮次的页脚并传入收尾回复的 seq，无法挂在运行中的轮首、事件或精确工具行；再加一份独立列表会重复位置解析，且仍无法把卡片限定到实际展示的 Session。

**让插件自己从 Chat 快照解析位置。** 否决：已加载行集合、分页、折叠与侧边留白都由宿主拥有；插件自行读取行位置会重复宿主解析，并在视口变化时漂移。

**用固定的媒体或容器断点决定侧边布局。** 否决：内容宽度自适应且可由用户调整，断点会在某些宽度下把卡片放到留白之外，或压成无法阅读的窄列。

**同时在侧边留白与轮内入口渲染卡片再隐藏一个。** 否决：两次挂载会重复注册，并在每次布局变化时丢失焦点与本地状态；一次挂载配合纯 CSS 位置保持卡片身份。

**让抛错的分类器清空菜单，或退回到客户端猜测。** 否决：宿主无法知道业务在别处提供了哪些原生条目；保留原生行是唯一可恢复的行为。

## Verification

`attachment-registry.client.spec.ts` 固定按 Session 发布、重复 ID、格式错误的锚点、撤回与卡片顺序。`attachments.client.spec.ts` 针对已加载轮次与行固定每种锚点，包括已加载行缺少轮首的轮次、精确 callId、重复 callId、未加载轮次、同一位置的注册顺序、「`anchorSeq` 与行相邻关系都不回答耐久事件」这条规则、解析到根行或所属过程组的 `step/start`、隐藏的首行、被呈现两次的节点，以及保留轮次入口的未知 seq。`attachment-layout.client.spec.ts` 固定测量出的留白判定与宿主分配：每侧只让一张 `auto` 卡进入留白，显式 `inline` 卡留在轮内且不占容量，同侧两张 `auto` 卡一起回退。`attachment-row.client.spec.ts` 固定同一位置的一行在两种登记顺序下都保留每张卡自己的 host。`catalog-classification.client.spec.ts` 固定合并顺序、撤回、revision 重新发布、抛错分类器、无法读取的结果、迭代中途失败的结果、证据订阅释放失败与监听器抛错。`conversation-ui.client.spec.tsx` 固定菜单行、总数、运行数、空态、原生地址与嵌套层级都读取同一份分类。[issue 18 浏览器用例](../../../../apps/web/tests/issue-18-host-probe.e2e.ts)使用真实 Web 脚手架、受控模型与不依赖 Nodes 的夹具插件，验证：宽视图下两侧卡片进入测量出的留白、窄视图的轮内位置与焦点保持、没有最终回复的已结束轮次、精确耐久事件锚点及其轮首回退、真实 `step/start` 步入口及其组开合、精确过程调用行经组与轮次入口的落位以及侧边空白、分页、不继承卡片的 fork、两种宽度下卡片出现与移动时的阅读位置与焦点稳定、显式 inline 历史入口留在轮内而 auto 活动卡取得留白与其原生行座位、inline 历史卡与 auto 活动卡在两种登记顺序下汇合于同一折叠轮次入口且每张卡保留自己的 host、同侧两张 auto 卡一起回退、侧边卡片下宽表保持在内容列内、长过程组在取消高度上限后的开合与滚动，以及菜单的分流、撤回与空态。跨仓库的真实 Nodes 用例与外部捕获的 Session 均为显式选用：仅当 `NODES_REPO` 与 `ISSUE18_CAPTURE` 指向对应输入时运行，干净检出只用自己的夹具。

## Consequences

宿主新增一个按 Session 的注册表、一个按键 Slot 与一次测量布局判定，业务只保留自己的卡片组件与锚点选择。精确 Tool 行在自身没有声明耐久来源事件时不报告 `seq`，因此业务必须依赖目标 callId，而不能假定存在耐久位置。`event` 锚点定位已加载根行或已加载 Step 入口：由嵌套工具行拥有、没有对应行、也没有 Step 边界的事件保留该轮入口，精确工具行改用 `tool-call`。侧边布局需要测量出的留白，且每侧最多只用它承载一张 `auto` 卡片：多于一张时全部留在轮内，以未测量的遮挡风险换取留白，而业务标记 `presentation: 'inline'` 的卡片从不参与竞争。承载侧边卡片期间过程组取消高度上限，卡片移走前该组会比其上限形态更高；侧边卡片存在期间还会限制其留白里的宽表越出。
